# UI prototype

Build materially different UI directions on one isolated route.

Required behavior:

- provide at least three variants when the user did not request a specific count;
- switch variants with a query parameter and visible selector;
- keep Thai content, data, and required capabilities constant;
- exercise desktop and narrow mobile widths;
- keep semantic HTML, keyboard access, focus visibility, and readable contrast;
- use existing typography, tokens, shadcn source, and Lucide icons where applicable;
- use portrait Poster and three-image Gallery constraints in Work examples.

Vary information hierarchy, density, navigation, and interaction model, not only colors. Label every variant and state the question it is testing. Avoid polished animation until the direction is chosen.
