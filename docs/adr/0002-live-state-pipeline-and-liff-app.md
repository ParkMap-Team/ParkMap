# 0002: Live state pipeline and LIFF app

Status: accepted, 2026-09-30. Supersedes the process layout and the "vinext stays" note in 0001; the rest of 0001 stands.

## Decision

**Processes.** One Python project, `apps/vision-api`, with two entrypoints from the same code and image: `uvicorn app.main:app` (API) and `python -m app.worker` (worker). The worker runs on-premises on the camera network; the API, Postgres, and the LIFF app run on Coolify. The worker pushes derived JSON to `POST /api/internal/parking-states` with a bearer worker token. Raw frames and footage never leave the camera network.

**Frames.** The worker keeps only the newest frame in an in-process slot and drops superseded frames. No Celery, Redis, or external queue: one camera per worker, and the analysis cadence (about 2 to 5 s) is slower than the camera.

**Storage.** Postgres, owned by the API through SQLAlchemy 2.1, Alembic, and psycopg 3. Tables live in schema `parkmap`, not `public`. Only standard Postgres features are used, so a later move to Supabase Postgres is a connection-string change (session pooler or direct connection; the transaction pooler needs `prepare_threshold=None`, not configured yet). No ORM runs in the web app; Prisma was rejected because Python owns the data and the Python Prisma client is archived. Parking states are append-only JSONB rows purged after 30 days by `python -m app.manage purge-states`.

**Trust.** A published state carries `calibration_version`, a SHA-256 fingerprint of the calibration files the worker used. The API serves regions only when the area has an active calibration with the same version and the observation is younger than `PARKMAP_STATE_FRESHNESS_S` (default 15 s). Otherwise the area is `STALE`, `NO_DATA`, `NOT_CALIBRATED`, or `CALIBRATION_MISMATCH` and carries no regions. Rows whose parking-state decision is invalid or `UNCERTAIN` are published as `UNKNOWN`, never as available. Every state carries a source kind (`LIVE_CAMERA`, `RECORDED_REPLAY`, `SYNTHETIC_FIXTURE`) and the LIFF app must announce non-live sources.

**Geography.** Site, then parking area, then exactly one camera. A parking area is observed by one camera; larger coverage adds cameras for further non-overlapping areas, never fused views. The first release uses one camera covering about a quarter of the lot. The static lot model (outline plus parking areas, in metres) is stored per site as versioned JSON; ground outside every parking area is served as `unmonitored`. Multi-camera sites later need per-area transforms into one site frame.

**LIFF app.** New `apps/liff` on standard Next.js (App Router, Tailwind v4, shadcn). It is student-facing only. The browser polls a Next Route Handler every 4 s with TanStack Query; the handler calls FastAPI server-side and allows 2 s of shared caching. Server Actions are for mutations only. The 3D view uses react-three-fiber with a procedural lot from the lot model and motorcycle proxies from detections. The MVP only runs `liff.init`; it does not read LINE identity. The POC `apps/web` moves to `tools/calibration-ui` and stays on vinext.

**Contract.** Pydantic models are the source of truth. `apps/vision-api/openapi.json` is committed and generated by `scripts/export_openapi.py`; `apps/liff` generates `src/lib/api/schema.gen.ts` from it with `openapi-typescript`. CI fails when either is out of date. No shared package.

## Why

The worker needs camera-network access that a hosted API does not have, and the API needs a public address the camera network should not expose. Pushing derived state keeps footage local and lets either side restart independently. A stale or mismatched state is worse than none, because a false green sends a rider into a full lot, so every decision that can show green is made on the server with explicit freshness and calibration checks.

## Consequences

- A camera outage or clock skew shows as `STALE`, not as old availability.
- Changing calibration files without running `python -m app.manage register-calibration` hides the area as `CALIBRATION_MISMATCH` until it is registered.
- Calibration POST endpoints are still unauthenticated development facilities and must be protected before the API is public.
- Requirement files and `requirements-dev.lock` stay until a separate move to `pyproject.toml` and `uv.lock`.
