# 0011: Still-image loop demo on estimated calibration

Status: accepted, 2026-10-15. Extends [0005](0005-cloud-hosted-video-replay-demo.md) and [0004](0004-stand-in-data-is-not-accuracy-evidence.md).

Until the demo video exists, the worker can loop a directory of recorded photos from one fixed viewpoint. Each photo is named after its local capture time (`YYYYMMDD_HHMM[SS]`, offset set by `--photo-utc-offset`, default `+07:00`), must match the calibration reference resolution, and is shown for `--hold-s` while being re-analysed at the worker interval; the worker refuses to start on any photo it cannot describe. States publish under the new source kind `STILL_IMAGE_LOOP` with schema version 2, which adds `processed_at` (analysis time) beside `observed_at` (the photo's real capture time) and `calibration_provenance`. A still-image loop ages from `processed_at`, so a healthy loop reports the new area status `DEMO` and serves regions, while a stopped loop turns `STALE`; every other source still ages from `observed_at`. The latest state is chosen by `processed_at`, because the loop returns to older photos. The LIFF app permanently labels `DEMO` as recorded demo data and shows the photo time, never "now". Ground control points and measured rows may be `ESTIMATED` with an uncertainty in metres and an estimation basis; the calibration is `ESTIMATED` as a whole if any input is, physical rows are then `NOT_CHECKED`, and it makes no distance or accuracy claim. A `LIVE_CAMERA` state on an estimated calibration must report every region `UNKNOWN`, enforced by the worker and again at ingest, until every input is measured. Rejected: stamping photos with the current time, which would present recorded data as live, and blocking non-live sources until the lot can be measured, which keeps the demo pipeline idle for no safety gain. Accepted cost: schema version 2 rejects older workers, the `0002_processed_at` migration deletes stored parking states, and the loop shows only the occupancy captured in its photos.
